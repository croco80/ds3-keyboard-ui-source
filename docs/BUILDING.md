# Building and verification

## Exact release toolchain

The native binaries included in the four submitted Nexus ZIPs were built on
Windows x64 with:

- Microsoft C/C++ Optimizing Compiler 19.50.35727
- Microsoft Incremental Linker 14.50.35727
- x64 target
- Windows GUI subsystem

The repository build script locates Visual Studio with Microsoft's `vswhere`
utility and initializes the x64 developer environment automatically.

## One-command native build

From the repository root:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\build-native.ps1
```

To choose another output folder:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\build-native.ps1 `
  -OutputDirectory C:\Temp\ds3-ui-build
```

The script performs these transparent operations:

1. Creates minimal `KERNEL32.dll` and `USER32.dll` import libraries from the
   checked-in `.def` files.
2. Compiles the XInput proxy and launcher with:

```text
/O2 /GS- /GR- /EHsc- /Zl /std:c++17
```

3. Links the proxy with:

```text
/DLL /DEF:XInput-Proxy-EXPORTS.def /ENTRY:DllMain
/SUBSYSTEM:WINDOWS /NODEFAULTLIB /OPT:REF /OPT:ICF
```

4. Links the launcher with:

```text
/ENTRY:LauncherEntry /SUBSYSTEM:WINDOWS
/NODEFAULTLIB /OPT:REF /OPT:ICF
```

The code supplies its own small `memset`/`memcpy` implementations and uses the
minimal Win32 declarations in `Win32-XInput-MINIMAL.h`, so no C/C++ runtime DLL
is imported.

## Expected structure

The proxy exports named XInput functions at ordinals 2 through 8 and unnamed
compatibility exports at ordinals 100 through 103. Its only imported module is
`KERNEL32.dll`.

The launcher imports only `KERNEL32.dll` and `USER32.dll`.

The release files have these sizes:

| File | Size |
| --- | ---: |
| `xinput1_3.dll` | 17,920 bytes |
| `DS3 Seamless + Keyboard UI.exe` | 6,144 bytes |

The script checks these imports, exports, and sizes after linking.

## Hash correspondence

The exact release hashes are in `docs/RELEASE-MANIFEST.md`. Microsoft LINK
embeds a build timestamp, so a normal rebuild at a later time has a different
SHA-256 even when the executable code and layout are otherwise identical.

Using the same 19.50.35727 toolchain and checked-in sources produced files with
the exact same sizes and only six timestamp bytes different from each submitted
binary: the PE COFF timestamp and the corresponding debug-directory timestamp.
This is documented to avoid presenting a timestamp-adjusted file as a fresh
compiler output.

## Release verification

To verify an extracted Nexus package:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\verify-release.ps1 `
  -ReleaseDirectory "C:\Path\To\Extracted\Ashen Iron"
```

The verification script checks the exact submitted proxy and launcher hashes
and reports the hashes of the included third-party runtime files.

## Artwork build

The original keycap geometry is rendered with Python and Pillow 12.3.0. The
release used the Georgia fonts installed with Windows; no font file is included
in the mod or repository.

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-artwork.txt
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\render-artwork.ps1 `
  -Python .\.venv\Scripts\python.exe
```

The render output contains 512 x 512 editable masters, 32 x 32 final PNGs, and
preview sheets. The exact output PNGs packaged with the releases are retained
under each `artwork/<style>` directory for inspection.

For the game archive, the 32 x 32 PNGs are converted to BC7 DDS using
DirectXTex and replace the 17 mapped prompt entries in the permitted menu
archive from Nexus mod 823. The mapping is listed in each style's
`TEXTURE-MAP.txt`. Packaging does not change any game executable.

The separately stored 16:10 `.gfx` files are the unchanged assets from Nexus
mod 1832. They are not generated by this repository and are not claimed as
original source.
